How it works

  1. $ describe

    Say what the code was supposed to do, in plain language.

  2. $ paste

    Drop in the function, component, or file that isn't behaving — any language.

  3. $ console

    Add the error if there is one. No error at all works too.

  4. $ diagnose

    Get the bug, why it happens, and a fix you can copy straight into your file.

What it's built for

Reads intent, not just syntax Most linters catch typos. DebugAI catches the gap between what you meant and what you wrote.
Works without a stack trace Silent logic bugs — wrong scope, off-by-one, stale closures — get diagnosed from code and intent alone.
Any language, no setup Paste and go. No install, no linking a repo, no sandboxed execution of your code.
A fix you can copy, not a paragraph to decode Every diagnosis ends in working code, ready to paste back in.

The three things that have to agree

A bug is just a disagreement between three things: what you meant, what you wrote, and what the console says happened. DebugAI's whole job is finding which edge broke. Toggle the code below and watch the triangle react.

Real diagnoses

🔴

variable scope issue — line 3

var i is function-scoped, so every click handler shares the same i — by the time setTimeout fires, the loop has already finished. 

1for (let i = 0; i < items.length; i++) {2  items[i].addEventListener("click", ...);3}
🔴

TypeError — line 3

res.json() returns a Promise. Without await, user is the Promise itself, so user.name is undefined. 

1const res = await fetch(url);2const user = await res.json();3nameEl.textContent = user.name;
